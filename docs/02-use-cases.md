# ユースケース（画面との対応）

「こういうとき、どの画面で何をするか」を並べたもの。◎＝そのまま使える、○＝できるが導線か表示が弱い、✗＝無い。
✗と○は候補として下の「足りないもの」にまとめる。2026-09-21（v0.1.15）時点。

---

## A. 仕入 → 出品 → 販売 → 入金（メインの流れ）

| # | やること | 画面・操作 | 今 |
|---|---|---|---|
| A1 | 取引（仕入）を登録する | メロジョイ：取り込みで自動（価格未入力は要対応→確定）。TikTok など：仕入タブ「仕入を登録」／「CSV で一括登録」。送料は仕入先の既定値 | ◎ |
| A2 | 配送状態を確認する | メロジョイ：取り込みで自動更新。手入力：行の「配送」で 未発送／配送中／到着済 | ◎ |
| A2' | 追跡番号・到着の目安を見る | ― | ✗（注文状況ページの追跡番号→17TRACK リンク、過去実績から「到着の目安 n 日」を出す案） |
| A3 | 在庫に反映される | 確定した瞬間に数量分の在庫。届くまで「未着」の印 | ◎ |
| A4 | 出品する前に、家に届いている在庫を確認してコードをコピー | 在庫タブ「未出品」→ コードのチップをタップ（`【S-0012】`） | ○（「届いている＝到着済だけ」の絞り込みが無い。未着の印を見て避けるしかない） |
| A5 | 出品する → アプリに載る | メルカリで出品 → 取り込みで売上タブ「出品中」に並ぶ。型番が一致すれば自動引き当て | ◎ |
| A6 | 想定の配送（発送方法）を決めておく | 出品中の行の発送方法セレクト。売れたときそのまま販売に入る | ◎ |
| A7 | 出品後に在庫を引き当てる（手で） | 出品中の行「引き当て」→ 在庫にチェック（見込み粗利が出る）。「型番で自動引き当て」 | ◎ |
| A8 | 売れた → 状態を見る | 取り込みで取引中タブを読み「発送してください」。ホーム要対応「発送してください n 件」 | ◎ |
| A9 | 発送する（メルカリで発送通知） | メルカリ側の操作。次の取り込みで「受取評価待ち」に進む（後戻りしない） | ◎ |
| A10 | 到着待ち・評価待ち＝**まだ入金されていない** | 売上の状態チップ（受取評価待ち／評価待ち） | ○（「入金待ち n 件 ¥」「入金済 ¥」の合計が無い。状態の言葉も「入金待ち」になっていない） |
| A11 | 評価まで終わる → 入金 | 販売履歴に出た時点で「取引完了」 | ○（同上。「入金済」と読めるようにする） |
| A12 | 送料・紐付けを入れて利益を確定 | 売上「売れた・要入力」→ 発送方法／紐付け → 利益確定へ | ◎ |

## B. 滞留している商品をどうするか

| # | やること | 画面・操作 | 今 |
|---|---|---|---|
| B1 | 滞留している在庫を見つける | ホーム「長期滞留 n 点」→ 在庫タブ（滞留日数順） | ◎ |
| B2 | いつ買った？いくらで？ | 在庫の行：仕入日・原価。行を開けば仕入の取引詳細 | ◎ |

| B4 | この金額で売ったら利益はいくら？ | ― | ✗（商品詳細に「売価を入れると見込み粗利」＝売価 − 手数料 − 発送方法の送料 − 原価、を出す欄） |

## E. 例外・修正

| # | やること | 画面・操作 | 今 |
|---|---|---|---|
| E1 | 引き当てを間違えた | 行の「引き当て」→ 外して付け直す（1 クリック） | ◎ |

| E6 | 送料が実額 ¥0（メルカリ便以外） | 送料未入力に戻り、発送方法を選び直す | ◎ |

## 足りないもの（候補。上の ○／✗）

1. **入金待ち／入金済**（A10・A11・C3）：状態を「入金待ち（発送済み・受取待ち・評価待ち）」「入金済（取引完了）」と読める言葉にし、売上サマリに「入金待ち n 件 ¥」を出す
2. **この金額で売ったら利益は？**（B4）：商品詳細に売価入力 → 見込み粗利（手数料率・発送方法・原価はその型番の未出品在庫の先入先出 1 点）
3. **在庫の型番チップ → 商品詳細**（B3）：1 クリックで飛ぶ
4. **到着済だけ**の絞り込み（A4）：在庫「未出品」に「届いている在庫だけ」
5. **追跡番号・到着の目安**（A2'）：発送済みの注文状況ページの HTML を見てから
6. **確定済み仕入の編集**（E3）：未販売のときだけ数量・単価・送料を直せる
7. 出品中のタグ絞り込み（D1）：引き当てた在庫の派生タグで
