# そろばん（Soroban）

メルカリ転売の利益管理ツール。単一のElectronアプリ、ローカルSQLite、外部サービスなし。

```
いつ・何円で仕入れた商品が
  → どの販売に対応して
    → 手数料と送料を引いて
      → 何円の利益になったか
```

---

外部サーバーもクラウドDBもない。データはこのPCの中だけにある。

## 最初にやること

1. アプリを起動する
2. 右上の**「メルカリにログイン」**を押し、開いたウィンドウで普通にログインする
   - ログインできたらウィンドウを閉じる
   - 以後はセッションが再利用されるので、この操作は不要
3. **設定**タブで発送方法の送料を確認する（初期値が入っているが、改定されている可能性がある）
4. **仕入**タブで「仕入先を追加」→ メロジョイA / メロジョイB を登録する
5. 右上の**「取り込む」**を押す

## 毎日の運用

### 起動するだけ

前回から1時間以上空いていれば、起動時に裏で取り込む。間隔は設定で変えられる。

### 売れたとき（1件10秒）

**売上**タブを開き、新しく入った販売に2つだけ入力する。

1. **発送方法を選ぶ** → 送料が自動で入る
2. **「紐付け」を押して在庫を選ぶ** → 原価が入り、粗利が確定する

紐付けパネルでは、商品名が近い在庫が上に並ぶ。チェックを入れると
その場で粗利が計算されるので、見ながら確定できる。

まとめ売りなら複数チェックする。私物を売った場合は「転売」バッジを押して
「私物」に切り替える。紐付けは不要。

### 仕入れたとき

**仕入**タブから登録する。注文日・商品・単価・数量・送料。

登録すると、数量分の在庫が自動生成され、送料が按分される。
送料1,000円で5点なら、1点あたり200円が原価に乗る。

### 月に1回

- **在庫**タブの「月次」で集計を確認する
- **設定**タブから**バックアップ**を取る（ローカル1ファイルなので必須）
- 長期滞留している在庫を確認する

## トラブル対応

### 「ログインが必要」と出た

セッションが切れている。右上の「メルカリにログイン」から入り直す。

### 取り込みが0件のまま

**放置しないこと。** メルカリの画面構造が変わって、セレクタが壊れている可能性が高い。

このアプリは0件を「正常」ではなく `empty` という**異常**として記録する。
設定タブの実行履歴に `0件` が連続していたら壊れていると判断してよい。

直し方は `src/main/collector.ts` の `scrape()` を参照。
実際の売却済み一覧を DevTools で確認しながらセレクタを調整する。

### 利益が合わない

1. 仕入の送料按分が正しいか（仕入タブで総原価を確認）
2. まとめ売りの紐付けが漏れていないか
3. 発送方法の送料マスタが現在の料金と合っているか
4. 私物と転売が混ざっていないか

## 設計上の約束

| 項目 | 理由 |
|---|---|
| 認証情報を保存しない | プロファイルのみ保持。2段階認証にも対応できる |
| 書き込み操作をしない | 読み取り専用。出品・価格変更は行わない |
| 既定1時間間隔 | 人間と同じ速度で数ページだけ読む。CAPTCHA が出たら止める |
| 0件を異常として扱う | 静かな欠損が一番怖い |
| 金額は整数（円） | 浮動小数点の誤差を持ち込まない |
| 在庫の原価は生成時に確定 | 後から仕入を直しても過去の利益が動かない |
| 手数料率を変えても再計算しない | 同上 |
| 紐付けは自動確定しない | 誤紐付けは原価を壊し、気づきにくい。例外は型番の完全一致だけ（Phase 2） |
| 在庫は1点単位 | まとめ売りに対応するため |

## 留意事項

### 自動取得について

メルカリの利用規約は自動アクセスを制限している可能性がある。
自分のアカウントの自分のデータを低頻度で読むだけの設計にしているが、
アカウント停止のリスクがゼロとは言えない。頻度を上げない、書き込みをしない、
挙動がおかしければ止める、を守ること。

より安全な代替として、売却通知メールをGmail APIで読む方式がある。
メール文面はDOMより安定しており、規約上の懸念も少ない。

### 税務・法務について

所得区分（雑所得か事業所得か）、私物売却との切り分け、古物商許可の要否は、
税理士などの専門家に確認すること。このツールは集計を助けるだけで、判断は代替しない。
